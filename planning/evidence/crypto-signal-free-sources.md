# Free/self-hosted X collection options for an Agent Skill

**Checked:** 2026-08-31  
**Scope:** Batch collection of public posts from a configurable account list without a paid X API. Evidence below favors project-owned repositories, READMEs, source, releases, licenses, and X's own terms.

## Bottom line

The strongest installable core is **[twscrape](https://github.com/vladkens/twscrape)**: it is MIT-licensed, actively released, supports both user timelines and search, stores account sessions in SQLite, accepts cookie-based login, tracks rate limits per account and endpoint, and can use a per-account, process-wide, or CLI proxy. For an RSS-shaped deployment, **[RSSHub](https://github.com/DIYgod/RSSHub)** is the best maintained option. **[x-tweet-fetcher](https://github.com/ythx-101/x-tweet-fetcher)** is the most Agent/CLI-friendly adapter and local archive, but its timeline/search path relies primarily on Nitter or browser fallback.

There is an unavoidable qualification: X's current [Terms of Service](https://x.com/en/tos) say that crawling or scraping in any form requires prior written consent and prohibit accessing/searching by automated means other than X's published interfaces unless separately allowed. X's official API is currently [pay-per-use](https://docs.x.com/x-api/getting-started/pricing). Therefore, no zero-cost scraper described here is both officially authorized by default and robust at production scale. Use only after an explicit legal/ToS decision; collect public data at low frequency, do not evade controls, and expect account or IP enforcement.

### Source-available but not genuinely open-source

**[Tweet Harvest](https://github.com/helmisatria/tweet-harvest)** is often suggested as a free Playwright CLI and does support X search queries (including `from:user` expressions), but its repository [license](https://github.com/helmisatria/tweet-harvest/blob/main/LICENSE) restricts use/modification to educational, non-commercial purposes. That fails the Open Source Definition's no-field-of-endeavor restriction, so it should not be represented as genuinely open-source. Its [README](https://github.com/helmisatria/tweet-harvest#readme) also requires a valid account's auth token. Latest checked release: [v2.7.1 (2025-12-16)](https://github.com/helmisatria/tweet-harvest/releases/tag/v2.7.1).

## Proxy and network choices

| Approach | Cost / friction | What primary sources establish | Recommendation |
| --- | --- | --- | --- |
| **Direct local/VPS connection** | Free; lowest setup | twscrape, RSSHub, gallery-dl, and Playwright all operate without a proxy. | **Default.** One stable egress IP is less suspicious than churn and avoids disclosing traffic metadata to another operator. Add jitter/backoff rather than IP rotation. |
| **Local Tor SOCKS proxy** | Free; install Tor locally | twscrape accepts SOCKS URLs (`TWS_PROXY=socks5://...`) in its [proxy docs](https://github.com/vladkens/twscrape/blob/main/readme.md#proxy). Tor confirms that sites may [block Tor exits](https://support.torproject.org/tor-browser/general/website-blocking-tor-exits/) and that changing circuit changes exit IP in its [CAPTCHA guidance](https://support.torproject.org/tor-browser/encountering-issues/captchas/). | **Optional privacy experiment, not a reliability strategy.** Shared exits commonly trigger blocks/CAPTCHAs. Do not rotate a logged-in X account rapidly across exits. Tor does not make prohibited scraping permissible. |
| **Self-hosted Nitter/RSSHub** | Free software plus your host/IP/account | Nitter requires real session tokens; RSSHub requires X auth tokens for the unofficial Web API route. | **Reasonable RSS boundary**, especially RSSHub, but it does not remove authentication, rate limits, ToS exposure, or the need to protect cookies. |
| **Community Nitter instances** | Free and easy | Nitter's [README](https://github.com/zedeus/nitter) points to community instances; x-tweet-fetcher's maintainers explicitly say [public instances are unreliable and frequently dead](https://github.com/ythx-101/x-tweet-fetcher/blob/main/README.md#-self-hosted-nitter). | **Best-effort fallback for public data only.** Never send account cookies or secrets to a community instance. Instance operators can observe requested accounts, timestamps, and client IPs. |
| **Public proxy lists** | Free, minimal setup, unknown operators | Repositories such as [TheSpeedX/PROXY-List](https://github.com/TheSpeedX/PROXY-List) describe lists scraped from free public proxies and periodically checked; this establishes reachability, not operator identity, confidentiality, durability, or permission to relay X traffic. | **Reject for authenticated collection.** Unknown relays can log destinations/timing, tamper with non-TLS traffic, disappear, or be pre-blocked. Never expose X cookies, proxy credentials, or disabled TLS verification to them. |
| **Paid residential proxy services** | Paid; often priced by traffic | Bright Data's official [residential pricing](https://brightdata.com/pricing/proxy-network/residential-proxies) is pay-as-you-go/per-GB; Oxylabs publishes separate [residential proxy pricing](https://oxylabs.io/pricing/residential-proxy-pool). | **Out of scope for a free design.** They may improve IP diversity but add cost, vendor/data-provenance review, and no ToS authorization. Do not treat residential rotation as an ethical loophole. |

## Recommended Claude Code Agent Skill architecture

### 1. Stable skill contract

Use a small manifest rather than embedding accounts in code:

```yaml
accounts: [xdevelopers, coinbase, ethereum]
per_account_limit: 40
batch_size: 3
minimum_poll_minutes: 15
include_replies: false
include_retweets: true
backend_order: [twscrape, rsshub, xtf-browser]
```

The skill should expose `collect`, `backfill`, `search`, and `health` commands. Normalize all backends to one record (`post_id`, author ID/handle, created time, text, URL, reply/retweet/quote flags, media, raw source, fetched time), write JSONL, and deduplicate by `post_id` in SQLite. Store a per-account newest ID/cursor so normal runs fetch incrementally rather than re-reading full timelines.

### 2. Backend order

1. **Primary — twscrape:** one user-owned X session added from cookies, one stable direct IP, calls to `user_by_login` then `user_tweets`, at most 2–3 accounts concurrently. Use search only for explicit discovery/backfill, not as the default timeline path.
2. **RSS mode — self-hosted RSSHub:** one feed per configured account, useful when the caller already has an RSS scheduler/cache. Treat feed output as a transport; keep the same SQLite dedupe/cursor layer.
3. **Agent-friendly fallback — x-tweet-fetcher:** use its JSON/error contract and ledger. Prefer a self-hosted RSSHub/Nitter-compatible source; because Nitter is archived, do not make it a hard dependency.
4. **Browser fallback — Playwright through x-tweet-fetcher or a tiny dedicated adapter:** headed/manual login, local storage state outside the repository, strict request cap, selectors isolated behind fixtures. Disable automatically after repeated challenge/CAPTCHA responses rather than attempting bypasses.
5. **Media backfill — gallery-dl:** invoke only for selected post/account media after canonical post ingestion.

### 3. Safety and operational guardrails

- Require an explicit `--acknowledge-x-terms-risk` (or equivalent configuration) before enabling unofficial collection; print links to [X Terms](https://x.com/en/tos) and [automation rules](https://help.x.com/en/rules-and-policies/x-automation).
- Keep `auth_token`, `ct0`, Playwright storage state, proxy credentials, and SQLite account databases outside the project and logs with owner-only filesystem permissions. Never commit them.
- Default to direct egress, low concurrency, jittered intervals, exponential backoff, and a daily request ceiling. Respect 429/challenges; do not bypass CAPTCHA, create account farms, or rotate identities/IPs to defeat enforcement.
- Collect only public posts needed for the stated purpose; retain source URLs and timestamps; support deletion/expiry; do not collect DMs, private accounts, or unnecessary profile fields.
- Pin tool versions, include fixture-based parser tests, and make backend failures explicit. Unofficial X endpoints and DOM selectors can change without notice.
- Keep a provider interface so an authorized official or licensed provider can replace scraping later without changing the Agent Skill contract.

## Decision

For Claude Code users who can install Python/Node dependencies, build the skill around **twscrape + SQLite/JSONL**, with **RSSHub** as the maintained RSS option and **x-tweet-fetcher/Playwright** as explicit fallbacks. Use **direct local networking**, not proxy rotation. Tor may be offered as an opt-in privacy transport with a warning that it is often blocked; community Nitter is best-effort only; public proxy lists should be refused for authenticated sessions; paid residential networks are neither free nor permission to scrape.

The design is technically workable for low-volume, user-supervised research, but the correct production recommendation remains: obtain X's written permission or use its paid official API if contractual compliance and service reliability are required.
